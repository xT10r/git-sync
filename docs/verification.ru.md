## Проверяемые сценарии

Локальные Git fixtures: целевая ветка не default, fast-forward, переписывание истории, новый SHA с прежним деревом, no-op, удалённая ветка и недоступный remote. Контролируемый HTTP server проверяет передачу Basic/Bearer/anonymous и отказ аутентификации.

Файловый результат: прежний снимок не изменяется; ошибка rename при публикации сохраняет current; retry публикует уже подготовленный снимок. Закреплённый reader читает согласованную пару файлов при десяти обновлениях. Отдельно проверены запрет чужого root/другого repo identity, symlink root, второй writer, очистка interrupted preparation, восстановление current и cache init без origin.

Контракт неподдерживаемых возможностей: LFS pointers, symlinks и gitlinks отклоняются до публикации. Это явное ограничение, а не неполная выгрузка, выданная за успех.

Жизненный цикл: немедленный initial sync, periodic sync, объединение бурстов trigger, deadline, неблокирующий status, остановка worker/HTTP, bind failure, auth/HTTP methods/readiness, разделение успешных/ошибочных/no-op счётчиков. Реальный subprocess публикует две версии, сохраняет первую и штатно завершается от SIGTERM.

## Уязвимости зависимостей

Первый scan выявил пять module-only записей x/net v0.59.0. Выполнено обновление до v0.60.0 и повторная проверка.

Оставшаяся запись: GO-2026-5932, golang.org/x/crypto/openpgp. У записи нет исправленной версии; пакет не импортируется приложением, вызываемых уязвимых symbols не найдено. x/crypto необходим транзитивной зависимости go-git; исключать весь модуль без анализа нельзя. Это не обещание отсутствия любых уязвимостей: результат относится к использованной базе и текущему графу вызовов.

## Измерение no-op

BenchmarkUnchangedSnapshot, Go 1.27.2, Linux amd64, AMD EPYC 9V74, 10 итераций, локальный маленький Git repo: около 0.33 ms/op, 86664 B/op, 1110 allocs/op. Это короткое базовое измерение, не сравнение с прежней версией и не прогноз для сетевого/большого репозитория.

## Контейнерная регрессия и исправление

Первый GitHub Container smoke успешно собрал образ, но обнаружил зависимость стандартного file transport go-git от внешнего git-upload-pack. На хосте тесты проходили благодаря установленному Git, а в scratch-образе fetch не работал.

Исправление: file transport регистрируется при инициализации пакета как встроенный server/client go-git с загрузкой repository storage. Runtime-изменений protocol registry нет. Добавлен тест с пустым PATH для абсолютного пути и file URL; локальный transport больше не требует системного Git. После изменения повторены race/vet, обе версии Go, cross-build и vulnerability scan. Повторный container workflow проверяет исправление в реальном образе.

## Оставшиеся ограничения и выпуск

- Автоматическая очистка готовых снимков отсутствует; нужно определить retention/срок чтения и контролировать диск.
- Нет exponential backoff/jitter, SSH, полной поддержки LFS/submodules/symlinks, secret files и автоматического ремонта повреждённого cache.
- Windows runtime не реализован; Linux проверен, другие платформы/FS требуют runtime-проверок.
- Atomic pointer не гарантирует набор нескольких open без закрепления reader snapshot и не обещает power-loss durability.
- Runtime container workflow подготовлен, но его наличие само по себе не означает успешного прохождения.
- Новый root/path/metrics/API несовместимы с v1. Перед merge/release провести миграционную проверку в целевом окружении, включая storage class, UID/GID, секреты и возврат к прежнему образу/volume.

Ветки main и develop не изменены. Проверенные изменения сохраняются в feature/git-sync-reliability.
